# Playout computers (experimental)

## Using it (on trial)

On trial on the beta and alpha sites (`features.js`, `TimerFeatures.playout`; the Worker's `FEATURES`): elsewhere `playout.html` isn't served and the timer treats a playout computer as a plain view-only device.

For bigger shows with several operators: an audio operator with the walk-up stings, a video operator feeding the vision mixer, and so on. Each runs `playout.html` on their own computer. It follows the timer's run sheet and plays **their own** audio and video at the moments they choose. The timer doesn't know or control what a playout computer does; it just runs the show.

1. On the playout computer, open `playout.html` next to the timer (e.g. `beta.timed-show.com/p`, short for `beta.timed-show.com/playout.html`).
2. Pair it like an overlay: **share** → **Pair a computer** on the timer, type the 6-digit code on the playout computer, then type the number it shows into the timer's share panel.
3. The timer's run sheet appears. Click **+ cue** on an item and choose when: **At the start**, **When time's up**, **After** m:ss, **With** m:ss **left**, or **To finish** m:ss **before the end** (leave the time empty for *at the end*): it starts when it needs to so that it ends then, and if it's longer than the item it starts with the item, part-way in, so it still ends on time. Then **Choose the sound or video…** opens the same dialog as the run sheet editor's **+ sting**: a stock walk-up sting, a file or a folder of your own (**Custom file**), or one of your clips (**Edited sting**, the sting library). **✂** there makes a clip first.

Whatever you choose is copied into this computer's browser: cues play from here, whatever happens to the site or the network. An AIFF file is copied in as a WAV with exactly the same sound (Chrome and Edge can't play AIFF).

**✂ on a cue** opens the clip editor: just the part to play, fades, a loop and a trim. The file isn't cut.

**Mark start / Mark end:** while a cue plays on its own (its ▶, or its key, or an XL in Cue 1), **Mark start** and **Mark end** sit beside its ■. Listen, and when you hear where the clip should begin, press **Mark start**: the cue stops and the clip editor opens with the start half a second before that moment (for your reaction), the close-up on it as **▶ First 2 s** shows it, ready to fine-tune. **Mark end** does the same for the end (nothing taken off), as **▶ Last 2 s** shows it. **Save** keeps it; **Cancel** leaves the cue as it was. Cues an item run plays don't have them. Its loudness is shown against the level of the cue's output (see **Levels** below).

**Levels (loudness normalisation, per output):** every cue's loudness is measured as it plays (LUFS) when it's added, and each output plays all its cues as loud as its quietest one: the louder ones are turned down to it, so no cue is louder than the next (nothing is ever turned up). **Options → Levels** has a row for **Show** and for each sound card a cue uses, saying what its level is and which cue sets it (*Level: −17.8 LUFS, its quietest cue (Applause)*) and the biggest cut it makes (*The loudest, Walk-up 4, is turned down 13.0 dB*). There's nothing to set: add a quieter cue and the level drops. A cue already playing keeps the level it started at, so it never jumps; the new level applies from its next play (turning **Level** on or off, or the **Automatic levels** switch, is your own change, so what's playing follows at once). **Each cue's loudness** is beside its length: 🔉 and its LUFS once measured, 🔈 on the quietest of its output (it sets the level) and 🔊 on the loudest (the one turned down most; point at it to see by how much). While a big folder is measured, one file at a time, ⌛ marks those waiting and ⏳ the one being measured, and the level box counts them (*Measuring loudness: 37 of 120…*); after a reload, the ones not yet measured carry on. — means it's over 10 minutes (not measured: it plays as recorded), ⚠ that it couldn't be measured. Untick **Level** to play that output's cues as recorded (a ✂ trim still applies). **▶ Tone** plays the line-up tone (1 kHz) at that level on that output, to set the desk by; **■ Tone**, **■ Stop all** or **Esc** stops it. It can't start while cues are playing, and a cue starting stops it: no 1 kHz under the music. On or off is kept on this computer.

**The level box** (top right, above the audio countdown, and it stays there as you scroll) always shows each output's level and how much its loudest cue is turned down. Set the desk (▶ Tone helps), then click the box: it goes grey, meaning the desk is set for that level. It's amber until you first do. If the level changes later (a quieter cue added, or the quietest one removed), the box flashes: from then on cues may sound louder or quieter than the desk was set for. Adjust the desk, or just make a note of it, and click the box to stop the flashing. Starting **▶ Tone** on an output counts as a click for that output, since you're setting the desk by it.

**Automatic levels** (on unless you untick it) lets a new level take effect at once. Untick it and a new level waits instead: the cues keep playing at the level in use, the Levels panel turns amber and says what's waiting, and the level box flashes showing both (*−19.1 → −13.1 LUFS*). Clicking the box (or starting ▶ Tone) uses the new level, for cues already playing too.

**Console trim** (in the level box, and beside each output in Options → Levels) saves lining up with the tone every time the level changes. It's the makeup gain the desk needs: when the level drops 3 dB, the console trim goes up 3 dB, so setting the desk's digital trim to it keeps the room where it was. Calibrate once: with the desk sounding right, set that output's **LUFS trim offset** so the console trim reads what the desk's trim is at (to read 0.0 dB at −17.8 LUFS, the offset is −17.8). After that, whenever the level changes, set the desk's trim to the console trim. No trim on the channel? A compressor's makeup gain does the same, with the compressor itself out of the way (a 1:1 ratio, or a threshold it never reaches). Each output has its own offset, kept on this computer.

**During the show:** each cue plays once each time its item runs, and plays on into the next items until it ends or you stop it. **Back** on the timer stops whatever is playing here. A playout computer that connects (or reloads) in the middle of an item doesn't replay a cue whose moment has passed, except a start cue within 2 seconds of the start. Time cues count running time: a pause holds them. Several cues at the same moment all play: audio cues together, video cues one at a time (the one lower in the item's list stays on screen).

**Changing a cue:** **✎** changes when it plays (the trigger and its time); **✂** changes the part of the file it plays.

**Your own text for an item:** **✎** on an item (beside its length) opens a box holding its name. Change it, or add notes on the lines under it (Enter starts a new line), then **Save** (or Ctrl+Enter, ⌘+Enter on a Mac). The first line is shown in place of the item's name, in the list and on the status line's *Now*; the rest shows as notes under it. It's kept on this computer only: the timer and every other screen still show the timer's name. Like the cues, it belongs to the item, so it stays when the run sheet is revised. If the timer renames the item afterwards, a line under it says what the timer calls it now, until you open ✎ and **Save** again. Saving the timer's name unchanged, an empty box, or **Use the timer's name** goes back to the timer's. **Cancel** closes the box without changing anything; **Esc** in the box still fades out what's playing (the box stays, with your text).

**Random stings:** **Random stings** under the run sheet works as the run sheet editor's: **🎲 Roll stings** gives every item long enough to be a speaker (2 minutes unless changed) a walk-up sting **At the start**, picked at random, none used twice (a cue you chose counts too), and copied to this computer like any cue. Choose where they come from: the stock stings, a folder of your own (leaving out files ticked *Exclude this from random selection pools* under the folder's list in + cue's **Custom file**), your clips (an edit stands in for the track it came from), and if you like only stings of a certain length, or (on trial on alpha) **only some styles**, lit as chips (*Rock (33)*, *Punk (6)*, *House (25)*…; your own files too, once this computer has listened to them, by itself, after you tick the folder or My clips). The **+ cue** dialog's stock list shows each sting's style and has the same chips, as the run sheet editor's (see the stings guide). An item with a start cue of your own is left alone. **🎲** on an item picks another for it, keeping when and where the old one played (✎, its output menu); on an item with a start cue of its own it adds one beside it. Rolled cues show 🎲 instead of 🎵. **✂** on one makes it yours, so a roll leaves it alone. Items that have run, the one playing (following the timer) and one you started with ▶ Start item are never rolled. **Remove rolled stings** removes them all; your own cues stay. If there aren't enough stings for every item, it asks whether to reuse ones already chosen (the least used first, never the same as the item before or after).

**Manual control:** ▶ on any cue plays it now, for testing or by hand. Turn off **Follow the timer** to take over completely (rehearsals, say, where the order depends on who's there): nothing plays by itself and the timer's Back no longer stops anything here; ▶ still works, and **▶ Start item** runs an item's cues as if it had started then: its start cues at once, the others timed from that moment by this computer's clock (*When time's up* and *With … left* from the item's planned length). Starting another item drops the cues the last one hadn't played yet; what's playing plays on. **■ Stop item** stops its cues. While an item's cues play, its **■ Stop item** stays, in green (also once its time is up). If you start another item while one is still playing, the older one's **■ Stop item** flashes green, and so do the **■** of its cues still playing: you're playing more than one item at once. Press it to stop that item (the new one carries on), or leave it to play to its end. While an item runs this way its own cues' ▶ and ■ are locked, so the run stays in charge; **Options → Play and stop single cues of an item started here** frees them at once (for rehearsals). **Fade out** (or **Esc**) fades everything out over 3 seconds; **■ Stop all** stops it at once (and an item started here). **Hold to fade:** every **■** on the page (a cue's, **■ Stop item** and **■ Stop all**) works like a Stream Deck key: click it and it stops at once; hold it down and it fades (over the Stream Deck box's fade time, 5 seconds unless changed), turning orange, and stops wherever you let go. Fades by hand (Fade out, Esc, holding a ■ or a Stream Deck key) are even in decibels, so the sound dies away steadily rather than hanging on and dropping at the end.

**Rehearsal controls:** while something plays, a small **⏯ Rehearsal** badge sits under the audio countdown (top right). Click it for **⏸ Pause** / **▶ Resume**, **⟲ Restart**, **⏭ Last 10 s**, a slider to find a spot (it moves there when you let go) and **✂ Edit**, which pauses it and opens its file in the clip editor (a new cut is heard from its next start). They work on the cue the countdown shows (the one playing that ends last) and stay on it while it plays. Paused, its countdown waits; **Fade out** or **■ Stop all** still ends it. The badge is folded again whenever the page is loaded and when its cue ends, so it isn't used by accident during a show.

**Where you are in the list:** the item under the mouse is lit, and the last item you clicked (anywhere in it: a button, a cue, the item itself) keeps a blue outline, so you can find your place again. An item opened in the clip editor from the rehearsal controls gets the outline too, and is scrolled into view.

**Arranging the page:** the run sheet, Stream Deck, Output, Sound outputs and Options each have a title row: drag its **⠿** to move the panel up or down the page (or click ⠿ and press ↑ ↓), and click **▾** or the title to fold it away. The run sheet's list scrolls in a box of its own, so a long one doesn't push the keys and the output off the screen: drag its bottom right corner to make it taller or shorter, or turn on **Show all items** to see the whole list. The item that starts is scrolled into view. The arrangement is kept on this computer, separately for playout, the demo and the soundboard.

**Output:** video cues play in the **Output** box (one at a time). **Full screen (F)** fills this screen with it, to see how it looks. For the audience's screen, **To external monitor** opens a floating window: drag it to that screen and double-click it (or press **F** in it) for full screen; videos then play there and the Output box says *External playback activated*. **Play here instead** brings them back and leaves the window open and black, ready for next time (not while a video is playing there). Set the window up with nothing playing: while a video plays here and the window isn't open yet, **To external monitor** waits until it stops. Once the window is open, a video playing here moves to it and carries on from where it was (a break of a few frames). If an item you started with **▶ Start item** plays its video here rather than out there, **To external monitor** flashes blue and yellow until you move it or it stops. If the window is closed, videos come back here. After a reload of this page, click **To external monitor** again: it finds the same window. **Sound outputs** (Chrome and Edge) picks the sound card the cues play on and another for the ▶ previews and the clip editor, so you can listen on headphones during the show; if the show's card is unplugged, audio cues don't play (videos play silent) and a warning says so.

**A cue's own output:** the menu on each cue (**→ Show** unless changed) sends that cue to another sound card on this computer, for a cue that needs a channel of its own. A video can have **No sound**: its picture only, so an audio cue starting beside it replaces its soundtrack (the two start together but aren't locked to each other: fine for music, not for lip sync). If a cue's card isn't connected when it's due, it doesn't play (a video plays without its sound) and a note says why; it never goes to another output instead. A cue uses the output its menu shows when it starts; while it plays, the menu is locked (green: in use) until it ends or is stopped. (Changing **Show** in Sound outputs moves what's playing on Show at once.)

**Cues belong to items, not to the pairing:** they stay on this computer when the timer makes a new share code, and an item keeps its cues when the run sheet is revised with **Replace sheet** (rows are matched to the items already there) or edited as a CSV file (its **Id** column). Cues for items that aren't on the timer's run sheet are kept for when they come back; **Remove them** under the list deletes them.

**Connection:** the status line says **⚡ Connected directly** or **Connected via the server**. Either works for playout (the messages are small); via the server, start cues fire after the trip through it. A browser that never connects directly, even next to the timer, may have WebRTC limited: Opera with its VPN sets *Disable non-proxied UDP* (search its settings for WebRTC and choose the default), then reload.

**Demo (no timer needed):** `beta.timed-show.com/p?demo`, or **Try the demo** on the pairing screen, shows the idea without a timer: ten made-up speakers of 20 minutes each, manual only (**Follow the timer** is off and locked), so cues play from **▶ Start item** and ▶. Everything else works as usual: cues, ✂, ✎, outputs, the external monitor. A demo's cues and levels are kept apart from a real show's. The names stay until **New speakers** (the cues stay with their places in the list); **Leave the demo** goes back to pairing.

**Soundboard mode (no timer at all):** `alpha.timed-show.com/s`, or **Soundboard mode** on the pairing screen, is the same page as a soundboard of your own: titled *Soundboard*, nothing to pair, and a run sheet you make yourself (kept apart from the demo's and a real show's).
- **+ Add item:** a name and a length (minutes, like `5`; m:ss, like `3:30`; h:mm:ss; or `90s`, `3m`; 20 minutes if you leave it empty).
- **Paste a list…:** one item per line, a name then its length if you like (after a comma, a tab or a space). A first line of *Name, Length* is skipped.
- **Drop a folder** (or files) anywhere on the page: an item for each audio or video file, in name order, named after the file, as long as the file, with the file as its **At the start** cue. Files in folders inside it count too, three levels down. On a tablet or phone, where you can't drop, **Add files…** does the same with the files you choose, and **Add a folder…** with a folder (not on phones or iPads, which can't choose a folder).
- On each item: **✎** renames it, sets its length and keeps notes on the lines under the name; **↑ ↓** move it; **✕** removes it and its cues.
- **Save…** writes the whole soundboard to a file: its items, their cues' settings, notes and the keys' arrangement, but not the audio and video files themselves. **Load…** reads one back, replacing what's there after asking. On the same computer the files are still here. On another, stock stings come back by themselves, and **Find files…** finds your own files in a folder you choose, by name and size.
- **Clear run sheet…** removes everything: items, cues, extra keys and their files.
- **Playlist flow** (a switch: lit while on): start an item and the rest follow it in the list's order, like a playlist. Each track crossfades into the next over its last 5 seconds (half a short track), evenly, so the middle doesn't dip; a video followed by a video doesn't overlap (there's one picture): the first plays to its end, then the next starts. Start another item (its key, or ▶ Start item) and the flow jumps there: what was playing fades out and the list carries on from the new one. **🔀 Shuffle** plays them in a random order instead: each item once (the next is picked ahead, so the line beside the chips names it), and a jump carries the round on from there. **🔁 Loop** goes back to the first item after the last (shuffled: a new round, never the track just played); without it, the last plays out and the flow ends. With **Crossfade on release** ticked (the Stream Deck box), a key that jumps the flow leaves the track playing alone until you let it go, then crossfades. **Minimal run sheet view** shows just the items (each with ▶ Start item), not their cues: it's always on (lit) with Playlist flow, and you can switch it on yourself at other times. The line beside them says what comes next. **■ Stop item**, **Stop all**, **Fade out** and Esc end the flow; turning it off lets the track playing finish on its own.
- **Leave soundboard mode** goes back to pairing.

Everything else works as in the demo: ▶ Start item, cues, ✂, levels, Random stings, the Stream Deck and phone keys. The **→ timer** key appears only while a timer page is open on this computer and has no deck; otherwise its key goes to the items.

**One tab at a time:** a playout page, its demo and the soundboard all share this browser's sound cards and decks, so only one tab runs one. Open another and it says *Playout is running in another tab* (or *Soundboard is…*, *The playout demo is…*), with **Use this tab instead**, which hands over to this tab: the other tab stops and says the same. When the running tab closes, a waiting tab takes over by itself.

**Stream Deck (a soundboard):** the **Stream Deck** box gives each item with cues a key, in run sheet order. With **Follow the timer** off (rehearsals, where the order depends on who's there), pressing a key starts its item, as **▶ Start item** does. On an item that's playing (or started here), the key stops it: a tap stops it at once, and holding the key fades it out (over 5 seconds unless changed in the box); let go before the fade ends and it stops right there. The last key does the same for everything (and the line-up tone). When the items don't fit, **◀** and **▶** before it turn the page. A **Mini** always has four items, with **▶** in the top right corner (above the last key): each tap shows the next four, and after the last page it goes back to the first, so tapping through follows the run sheet; it has no Give to the timer key. With Follow on, the keys show the run sheet (the live item in blue) and only stop or fade: the timer starts the items. A key shows the item's start on top (planned; **≈** and the expected time once the show is running late or early; when it started, once it has), its name as this computer shows it (your text, ✎), and its length; its colour says what it's doing: green while playing, amber when started here, orange while fading (whatever is fading it: a key held, Fade out or Esc, ■ All held, the playlist flow), blue for the item on now. When letting go of a key stops what it was playing, the key flashes white for a moment, so you can see it did stop.

**Crossfade on release** (tick it in the Stream Deck box): a key that starts something (an item, an extra key, or cue 1) while other cues are playing fades all of them out (but cue 1 leaves its own item's other cues playing, as its ▶ does) over the time beside it (5 seconds unless changed) from the moment you let the key go. So if the track playing isn't right, press the one you want and let go: a clean crossfade in one press. Keys on the page and on phones work the same way. A tap on a key that's playing still just stops it.

**Item or cue 1 (an XL):** the key just before **→ timer** says what the item keys play. **Item** (as above) starts the item. Tap it for **Cue 1**: each item's key then works like the ▶ / ■ beside that item's first cue (the one listed first), so pressing it plays that cue, and while it plays a tap stops it and a hold fades it. The item keys turn teal while it's on, so you can see at a glance which way they work. While an item runs from ▶ Start item, its key is locked just as the cue's ▶ is. Tap the key again for **Item**. It's kept on this computer. **Mark start / Mark end** on the deck: in Cue 1, while a cue plays from its key, the two keys just before **Item / Cue 1** become **Mark start** and **Mark end** (standing in for whatever is there, never ■ All or → timer), labelled with the cue's name; they do what the buttons beside its ■ do (the clip editor opens on the page), and go back to what they were when it stops.

**How long the audio has to go:** each cue's row shows when it ends, counted from its item's start (an *At the start* cue: its length; *After 0:30*: 0:30 plus its length; *To finish at the end*: the item's length), and the item's line shows when all its audio ends. While an item runs these count down, in green. The box in the top right corner (it stays put when you scroll) shows how long the audio playing has left, with its item's name; with more than one item playing, the one that ends last. Item rows also show their start time, as the keys do.

The same keys are on the page, under the list of decks, and work with the mouse the same way (press and hold to fade), so the soundboard works without a deck too. **On screen** picks the size of deck they're shown as, or **Custom size…** for any grid from 2 × 2 up to 20 keys across and 11 down (a tablet, or a big touch screen as the soundboard: 20 × 11 is XL-size keys on a 1920 × 1080 screen). A custom size has its own arrangement and no → timer key, and a phone opened from **Show on a phone…** starts at the same size. **⛶ Full screen** shows the keys on the whole screen, with the level box and what's playing beside them (above them on a screen taller than wide); ◀ ▶ still turn the page; Esc comes back. **Arrange keys** shows every page: drag a key onto another to swap them, or onto an empty key to move it there; **Done** when finished. The arrangement is kept for that size of deck (an XL and an MK.2 each have their own); items added later go at the end, and **Run sheet order** forgets the arrangement.

**Extra keys (media that isn't on the run sheet):** drag audio or video files from your computer onto an empty key of the keys on the page: the key plays that file when pressed (and, playing, a tap stops it and a hold fades it, as an item's), whether you're following the timer or not. An extra key says *extra* (or *video*) on top and its length at the bottom, where an item's length is. Drop several at once and they fill that key and the empty keys after it, in name order. **Add files to keys…** (beside + Page) does the same without dragging (a tablet or phone): the files you choose go on the first empty keys. Dropped on an extra key, the new file replaces it (you're asked first); an item's key doesn't take files. The extras are listed under the keys, where ▶ plays one, ✂ trims it and its menu picks its sound card, as for any cue; ✕ removes it and frees its key. On other sizes of deck they come after the items. **+ Page** adds a page of empty keys to drop files on (◀ ▶ then turn the pages), and **− Page** removes the last page once it's empty.

**Cutting a clip from the keys:** while the clip editor is open (✂ on a cue), the Stream Deck's keys (and the keys on the page, and a phone showing them) become the editor's: **▶ Part**, **First 2 s**, **Last 2 s**, **2 s before** (the start), **Play on**, **■ Stop**, **Mark start** / **Mark end** (as it plays), the start and the end moved **−** / **+** by the step (**nudge by**: 0.01, 0.1 or 1 s; on an XL the times are shown beside them), **Cancel** and **Save**. A Mini shows ▶ / ■, Mark start, Mark end, Cancel, Save and **more ▶** (the nudges). When the editor closes, the keys go back to the items. **No Stream Deck?** On a phone showing the keys (**Show on a phone…**), choose **Clip editor keys** in its size menu: the phone keeps the editor's keys, as big as they fit its screen, dim until an editor is open on this computer. While no editor is open but something is playing, the phone shows the **rehearsal controls** instead: what's playing and its time left, where it is, ⏸ Pause / ▶ Resume, −10 s, ⟲ Restart, +10 s, ⏭ Last 10 s, ✂ Edit (opens it in the clip editor on the computer) and ■ Stop (hold: fade). So in a rehearsal you can leave the console, work with the people on stage and run the playback from the phone.

**On a phone:** **Show on a phone…** shows a QR code: scan it with the phone's camera and the same keys open on the phone, as the size of deck shown on the page (the phone's menu changes it). The phone shows a 3-digit number: type it in the box that appears here, and it's in (one wrong try and that phone is out). The code disappears from the screen once a phone has picked it up; **Show the code again** brings it back for another phone. On the phone a tap and a hold work as on a deck, and its screen stays on. A phone let in comes straight back after a reload; **Revoke** takes the keys away from it, **New code** signs every phone out, and **Stop sharing** ends it (phones get the keys back with **Show on a phone…** again). Phones need the playout page open: it hosts them, through the pairing server.

**Which deck is whose:** quit the Elgato Stream Deck app first (it holds every deck), then **Connect a deck…** and choose it: it's used here from then on. Every deck the site may use is listed, with **Use here** or **Give to the timer**. **Disconnect** stops using a deck here: it shows Elgato's own screen, and neither this page nor a timer page uses it until you click **Use here** (or the timer's **Connect**). **Forget** makes this browser forget the deck altogether (for the timer page too, as the site's permission is withdrawn): **Connect a deck…** brings it back. On a computer that runs the timer too, the timer page uses the decks that aren't the playout's, and lets go of one the moment the playout page takes it (and the other way round), so a 15-key deck can run the show from the timer while a 32-key deck is the soundboard. **From the deck itself:** the key next to the last one, **→ timer**, hands that deck back to the timer page. In the timer's deck editor, put **Deck → playout** (under *Other*; on the deck it reads **deck → soundboard** or **→ playout**, whichever page is open) on a key of your layout, and the playout's **→ timer** moves to the same key, so that one key hands the deck back and forth. **Hold it to hand over:** the top row says **switching · to timer · in 3**, counting down (every other key blank); let go before the end and nothing happens. At the end it says **let go**, and the deck goes when you do, so the other page never starts with a key held. Either key works only while the other page is open in this browser (and the timer's only takes a deck when it hasn't got one), and is dimmed otherwise, so a deck is never handed to nobody. A deck handed back to the timer shows Elgato's screen for a moment, then the timer's keys. This works in one browser, with the timer and the playout from the same site: other browsers, and alpha against beta, can't see each other's choices, so forget the deck there (the timer's deck editor: **Forget deck**). Two decks here each have their own page. Decks are told apart by their serial number (not yet tried on real decks: if two of the same model get mixed up, tell us).
